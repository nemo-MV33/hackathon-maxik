# norfly — расписание и ДЗ ИРНИТУ в MAX

Чат-бот и мини-приложение в MAX для студентов ИРНИТУ. Трек «Образовательные решения».

- Бот: [max.ru/t692_hakaton_max_bot](https://max.ru/t692_hakaton_max_bot)
- Мини-приложение: https://nemo-mv33.github.io/hackathon-maxik/ (открывается кнопкой в чате с ботом)

## Назначение

Студенты 1–2 курса узнают о домашнем задании из общего чата группы, где оно теряется среди сотен сообщений, а расписание смотрят на отдельном сайте. norfly собирает в одном месте расписание своей группы и подгруппы и домашнее задание, привязанное к конкретной паре. Передаётся ДЗ через тот же чат группы в MAX — одной ссылкой.

## Основной пользовательский сценарий

1. Студент открывает бота в MAX и запускает мини-приложение.
2. Находит свою группу поиском (например, `ИСТб-25-1`) и выбирает подгруппу. Выбор запоминается.
3. Видит пары на сегодня: время, аудиторию, преподавателя. Текущая или ближайшая пара подсвечена («Идёт сейчас · ещё 40 мин», «Через 25 мин»). Есть вкладки «Завтра» и «Неделя».
4. Нажимает на пару и записывает домашнее задание. У пары в расписании появляется отметка 📚.
5. Нажимает «Поделиться с группой» и отправляет сообщение с ДЗ в чат группы через окно MAX.
6. Одногруппник нажимает ссылку в сообщении, мини-приложение открывается на экране «Одногруппник поделился ДЗ», и он сохраняет задание себе одной кнопкой.

Бот дополнительно умеет показывать расписание в чате, присылать напоминания о парах и вести ДЗ в групповых чатах.

## Состав и архитектура

```
┌─────────── GitHub Actions (каждые 3 часа) ───────────┐
│ scripts/export-schedule.js → API ИРНИТУ              │
│ webapp (Vite build) + data/*.json → GitHub Pages     │
└──────────────────────────────────────────────────────┘
                        │ HTTPS, статические файлы
                        ▼
MAX ── кнопка в чате ── мини-приложение (React + MAX UI + MAX Bridge)
 │                         └ ДЗ хранится на устройстве, передаётся ссылкой ?startapp=
 └── бот (Node.js, @maxhub/max-bot-api, long polling) ── API ИРНИТУ
```

| Компонент | Путь | Роль |
|---|---|---|
| Мини-приложение | `webapp/` | React 19, `@maxhub/max-ui`, MAX Bridge. Экраны: выбор группы, «Сегодня/Завтра/Неделя», пара и ДЗ, приём ДЗ по ссылке |
| Выгрузка расписания | `scripts/export-schedule.js` | Забирает группы и расписание на текущую и следующую неделю, пишет JSON для мини-приложения |
| Бот | `src/bot/` | Сценарии в чате MAX: расписание, профиль, групповые чаты, ДЗ, напоминания |
| Клиент ИРНИТУ | `src/irnitu/`, `src/services/` | Запросы к API, кэш, повторы, нормализация расписания |
| HTTP-сервер | `src/http/` | Раздаёт мини-приложение, `/health`, API расписания и профиля с проверкой подписи `initData` MAX |
| Хранилища | `src/storage/` | JSON-файлы с профилями пользователей и данными групповых чатов |
| Развёртывание | `.github/workflows/pages.yml` | Сборка и публикация мини-приложения, регулярное обновление расписания |

## Запуск через Docker

```bash
cp .env.example .env   # заполнить BOT_TOKEN и IRNITU_API_TOKEN
docker compose up --build
```

После запуска:
- бот начинает отвечать в MAX;
- мини-приложение открывается в браузере на http://localhost:3000;
- расписание выгружается в течение 1–2 минут после старта и затем обновляется каждые 3 часа;
- состояние сервиса: http://localhost:3000/health → `{"status":"ok"}`.

Остановка и повторный запуск:

```bash
docker compose down        # остановить, данные сохраняются в томе norfly-data
docker compose up -d       # запустить снова в фоне
docker compose down -v     # остановить и удалить сохранённые данные
docker compose logs -f     # смотреть логи
```

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `BOT_TOKEN` | да | — | Токен бота MAX, выданный организаторами |
| `IRNITU_API_TOKEN` | да | — | Токен API расписания ИРНИТУ. Без него приложение откроется без расписания |
| `IRNITU_API_URL` | нет | `https://schedule.istu.edu/api/` | Адрес API ИРНИТУ |
| `IRNITU_TIMEOUT_MS` | нет | `6000` | Таймаут запроса к ИРНИТУ |
| `IRNITU_RETRIES` | нет | `1` | Число попыток запроса к ИРНИТУ |
| `CACHE_DIR` | нет | `./data/cache` | Кэш ответов ИРНИТУ для бота |
| `PORT` | нет | `3000` | Порт HTTP-сервера внутри контейнера |
| `HOST_PORT` | нет | `3000` | Порт на машине, куда пробрасывается сервер (только для `docker compose`) |
| `MINI_APP_URL` | нет | — | Ссылка на мини-приложение для кнопки в боте |
| `API_ACCESS_KEY` | нет | — | Ключ для служебного доступа к API расписания |
| `INIT_DATA_MAX_AGE_SEC` | нет | `86400` | Срок действия подписи `initData` MAX |
| `DEV_USER_ID` | нет | — | Тестовый пользователь для локальной разработки, в `production` не действует |
| `EXPORT_INTERVAL_SEC` | нет | `10800` | Период обновления расписания в контейнере |
| `EXPORT_WEEKS` | нет | `2` | Сколько недель расписания выгружать |

Для публикации на GitHub Pages токен ИРНИТУ хранится в секрете репозитория `INRTU_API_TOKEN`.

## Зависимости

- Node.js 22 (минимум 20), Docker с Compose v2.
- Сервер и бот: `@maxhub/max-bot-api`, `dotenv` — версии зафиксированы в `package-lock.json`.
- Мини-приложение: `react`, `react-dom`, `@maxhub/max-ui`, сборка `vite` и `typescript` — версии зафиксированы в `webapp/package-lock.json`.
- MAX Bridge подключается скриптом `https://st.max.ru/js/max-web-app.js`.

## Внешние сервисы и интеграции

| Сервис | Для чего | Реальная интеграция |
|---|---|---|
| MAX Bot API (`platform-api2.max.ru`) | Работа бота | да |
| MAX Bridge | Данные пользователя, кнопка «Назад», окно «Поделиться», вибрация, параметр `startapp` | да |
| API расписания ИРНИТУ (`schedule.istu.edu`) | Группы, преподаватели, аудитории, расписание | да, публичный документированный API по токену |
| GitHub Pages и GitHub Actions | HTTPS-хостинг мини-приложения и регулярная выгрузка расписания | да |

Сертификат `platform-api2.max.ru` выдан российским удостоверяющим центром Минцифры, поэтому в репозитории лежит его публичный корневой сертификат `certs/russian_trusted_root_ca.pem` (скачан с Госуслуг). В Docker он подключается через `NODE_EXTRA_CA_CERTS`.

## Работа с данными

- **Расписание** — из API ИРНИТУ, данные реальные. В мини-приложении указано время обновления.
- **Профиль в мини-приложении** (группа и подгруппа) и **ДЗ** хранятся только на устройстве пользователя в `localStorage`. На сервер они не отправляются.
- **Передача ДЗ**: текст ДЗ, группа, дата и номер пары упаковываются в ссылку `https://max.ru/<бот>?startapp=hw1…` (до 512 символов). Ссылку пользователь сам отправляет в чат через окно MAX. Получатель видит содержимое и сам решает, сохранять ли его.
- **Бот** хранит профили и данные групповых чатов в `data/preferences.json` и `data/community.json` (в Docker — том `norfly-data`). Из данных MAX сохраняются только ID пользователя, имя и выбранная группа.
- Персональные данные несовершеннолетних, телефоны и сведения о здоровье не собираются.
- Время пар везде считается по Иркутску (UTC+8), поэтому у проверяющего из Москвы подсказки «Через N мин» совпадают с иркутскими.

## Тестовые данные

- Для проверки нужны только токены из первого слайда презентации — расписание настоящее.
- Группа для проверки: **ИСТб-25-1**, 1 подгруппа.
- Для разработки без токена ИРНИТУ `npm run dev` в папке `webapp/` подставляет демо-группы `ДЕМО-25-1` и `ДЕМО-24-2` со сгенерированными парами. Эти данные вымышленные и в сборку не попадают.

## Пошаговый сценарий проверки

1. Откройте [бота](https://max.ru/t692_hakaton_max_bot) в MAX и нажмите кнопку открытия мини-приложения.
2. Введите `истб 25` и выберите **ИСТб-25-1** → **1 подгруппа**.
   *Ожидается:* экран «Сегодня» с парами группы, внизу «Источник: расписание ИРНИТУ · обновлено …».
3. Переключите «Завтра» и «Неделя», пролистайте на следующую неделю стрелкой →.
   *Ожидается:* пары по дням, подпись чётной или нечётной недели, пар 2-й подгруппы нет.
4. Нажмите на любую пару, введите ДЗ, нажмите «Сохранить».
   *Ожидается:* «ДЗ сохранено», после возврата у пары в расписании отметка 📚 с текстом.
5. Откройте пару снова, нажмите «Поделиться с группой», выберите любой чат.
   *Ожидается:* в чат уходит сообщение с ДЗ и ссылкой. Если окно MAX недоступно, приложение копирует текст или показывает его для ручного копирования.
6. Нажмите ссылку из сообщения (можно с другого аккаунта).
   *Ожидается:* экран «Одногруппник поделился ДЗ» с предметом, датой и текстом; после «Сохранить себе» ДЗ появляется у этой пары.
7. Нажмите «Сменить» в шапке и выберите другую группу.
   *Ожидается:* расписание другой группы, ДЗ первой группы не показывается.

Локальная проверка через Docker: после `docker compose up --build` откройте http://localhost:3000 и пройдите шаги 2–4 в браузере. Функции MAX (окно «Поделиться», кнопка «Назад») в обычном браузере заменяются запасными вариантами.

## Известные ограничения

- ДЗ хранится на устройстве. Если студент не открыл ссылку, ДЗ у него не появится; при смене телефона или очистке данных записи пропадут. Для общего хранилища нужен сервер — в текущей версии он сознательно не используется.
- Кто угодно может поделиться ДЗ по ссылке: без сервера нельзя проверить, что пишет староста. Получатель видит содержимое до сохранения.
- Текст ДЗ ограничен примерно 600 символами — это лимит ссылки MAX.
- Расписание в мини-приложении обновляется раз в 3 часа, выгружаются текущая и следующая неделя.
- Бот работает, пока запущен процесс с его токеном; одновременно должен работать только один экземпляр.
- В веб-версии MAX часть функций MAX Bridge может быть недоступна — тогда вместо окна «Поделиться» приложение копирует текст или показывает его для ручного копирования.
